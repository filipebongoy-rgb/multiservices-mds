# Simplification UX MDS

## Parcours client

Le chemin nominal est désormais : accueil → choix du service → demande en trois étapes. L’accueil ne demande plus de décrire le problème avant le formulaire : la description n’est saisie qu’une seule fois dans la demande.

Depuis l’accueil, il faut 1 clic pour choisir un service, puis 1 clic sur « Demander cette prestation », puis 2 clics de progression (« Continuer ») et 1 clic d’envoi, hors saisie. Les photos initiales sont sélectionnées en une seule opération, avec aperçu et retrait individuel avant envoi.

## Suivi

Le suivi conserve une seule page privée. Une frise permanente présente : Demande reçue → Confirmée → En intervention → Terminée. Les détails, l’historique et les documents restent accessibles dans la même page mais ne concurrencent pas la progression principale.

## Limites conservées volontairement

Les confirmations contractuelles et tarifaires restent nécessaires lorsqu’une véritable décision financière ou de planning est demandée. Elles ne sont pas supprimées pour donner une illusion de rapidité. Aucun paiement réel, transfert ou validation implicite n’est déclenché par l’absence de réponse.

## Validation technique

Le typage, les tests métier et le build de production passent après la refonte. La base de données n’a pas été modifiée pour cette simplification UX.
